# Day 08: ERC-4626 与 DeFi 份额数学

## 今日目标

- 区分 assets 与 shares，理解价格并不是一个单独存储的变量。
- 掌握 deposit/mint/withdraw/redeem 及四个 preview 函数的舍入方向。
- 理解直接 donation、首存攻击和虚拟资产/份额缓解机制。

核心关系可以先近似理解为：

```text
shares = assets * totalSupply / totalAssets
assets = shares * totalAssets / totalSupply
```

实际实现还必须处理空仓、虚拟份额、decimals offset 和向上/向下舍入。

## 动手任务

1. 对每个 preview 函数写一个与实际操作结果一致的断言。
2. 构造 attacker 首存、直接 donation、victim 存款的序列，量化盈亏。
3. 增加 Invariant Handler，随机执行 deposit/mint/withdraw/redeem/donation。
4. 定义并验证 `totalAssets`、可赎回资产、合约 Token 余额之间的关系。
5. 增加 withdrawal fee，确保 preview/max/实际操作仍符合 ERC-4626。

## 评审问题

- underlying 是 rebasing、fee-on-transfer 或带回调 Token 时会怎样？
- `totalAssets` 是否可被外部价格或暂时性 donation 操纵？
- 极小输入会不会铸造 0 shares，却仍转入 assets？
- 集成方使用 preview 值时是否提供 slippage 边界？

## 完成标准

- 能解释每个操作为何向上或向下舍入。
- 能写出一次 donation 对早期和晚期存款人的影响。
- Stateful invariant 至少覆盖三个 actor 和五类操作。
